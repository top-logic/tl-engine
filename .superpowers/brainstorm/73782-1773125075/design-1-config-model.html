Design Section 1: Configuration Model

How background agents are declared in AgentRegistry config

Core Idea

A background agent is a regular agent with an additional <background> config block. Agents without this block remain conversational agents (unchanged behavior).

Today: ReviewAgent (hardcoded)
<agent name="ReviewAgent" tools="gitea.create_gitea_issue"> <system-prompt> You are a quality reviewer... </system-prompt> </agent> // ChatProcessor.java (hardcoded) if (agentRegistry.hasAgent("ReviewAgent")) { // manually trigger, manually serialize, // manually handle notifications... }
After: ReviewAgent (declarative)
<agent name="ReviewAgent" tools="gitea.create_gitea_issue"> <system-prompt> You are a quality reviewer... </system-prompt> <background scope="chat" authority="advisory"> <trigger type="post-turn" /> <input mode="chat-context" content="last-turn" /> <output-handlers> <notification severity="warning" /> </output-handlers> </background> </agent>

More Examples

Example: Pre-turn Security Gate (authoritative, can block)
<agent name="SecurityGate" tools="tl.executeTLScript"> <system-prompt> You are a security compliance gate. Analyze the user's request and the proposed response. If it violates business rules, return BLOCK: followed by the reason. Otherwise return PASS. </system-prompt> <background scope="chat" authority="authoritative" notify-on-block="true" block-message="This response was filtered by security policy: {reason}"> <trigger type="pre-turn" /> <input mode="chat-context" content="full-chat" /> <output-handlers> <audit-log /> </output-handlers> </background> </agent>
Example: Scheduled Compliance Agent (application-scoped, autonomous)
<agent name="ComplianceChecker" tools="tl.listInstances,tl.executeTLScript,gitea.create_gitea_issue"> <system-prompt> You are a compliance agent. Check all SensitiveRecord instances for data retention policy violations... </system-prompt> <background scope="application" authority="advisory"> <trigger type="scheduled"> <schedules> <daily time-of-day="02:00" /> </schedules> </trigger> <input mode="autonomous" trigger-message="Run your daily compliance check." /> <output-handlers> <audit-log /> <notification severity="error" /> </output-handlers> </background> </agent>
Example: Model Quality Agent (TLScript input, on-demand)
<agent name="ModelQualityChecker" tools="gitea.create_gitea_issue"> <system-prompt> You are a model quality agent. Review the model data provided and identify missing descriptions, naming violations... </system-prompt> <background scope="application" authority="advisory"> <trigger type="on-demand" /> <input mode="script"> <script> all(`myModule:MyType`) .map(t -> t.get(`name`) + ": " + t.get(`description`)) .toString("\n") </script> </input> <output-handlers> <notification severity="info" /> </output-handlers> </background> </agent>

Java Config Interface (sketch)

// On AgentConfig: @Name("background") BackgroundConfig getBackground(); // null = conversational agent // BackgroundConfig interface: interface BackgroundConfig { Scope getScope(); // CHAT, APPLICATION Authority getAuthority(); // ADVISORY, AUTHORITATIVE boolean getNotifyOnBlock(); // only for AUTHORITATIVE String getBlockMessage(); // template with {reason} TriggerConfig getTrigger(); InputConfig getInput(); List<OutputHandlerConfig> getOutputHandlers(); } // TriggerConfig — polymorphic: PostTurnTrigger // fires after each chat turn PreTurnTrigger // fires before agent responds ScheduledTrigger // wraps TopLogic SchedulingAlgorithm OnDemandTrigger // manual via REST API // InputConfig — polymorphic: ChatContextInput // serializes chat (last-turn or full) ScriptInput // evaluates TLScript AutonomousInput // just a trigger message ProviderInput // Java InputProvider class
