# Review Agent Design

## Overview

A background quality-assurance agent that silently monitors agent interactions and creates Gitea tickets when it detects issues. Runs automatically after each agent turn and can be triggered manually via a chat UI button.

## Requirements

- Analyze agent responses for: incorrect/hallucinated answers, bad delegation patterns, tool misuse, unhelpful responses, inefficiency
- Create structured Gitea issues when problems are found
- Run silently in the background — only surface to the user when an issue is detected
- Support both automatic (post-turn) and manual (button) triggers
- Follow existing configured-agent pattern (XML config, not hardcoded)

## Architecture: Post-Turn Configured Agent

The Review Agent is a standard XML-configured agent (`review-agent`) triggered by `ChatProcessor` after each main agent turn completes. It runs on a separate background thread and does not block the user-facing response.

### Review Agent Configuration

- **Name:** `review-agent`
- **Entry point:** `false`
- **Delegations:** None (leaf agent)
- **Tools:** `create_gitea_issue`
- **Model:** Configurable via XML (e.g., `claude-sonnet-4-20250514`)
- **System prompt:** Instructs analysis of serialized conversation data for quality issues across five categories: incorrect answers, bad delegations, tool misuse, unhelpful responses, and inefficiency. If issues found, call `create_gitea_issue`. If none, respond with "No issues found."

### Input Format

The conversation is serialized as XML and passed as the review agent's user message:

```xml
<review-request>
  <user-messages>
    [chronological user messages]
  </user-messages>
  <agent-responses>
    [chronological agent responses]
  </agent-responses>
  <tool-timeline>
    [tool calls with args and results]
    [agent delegations with inputs and outputs]
  </tool-timeline>
</review-request>
```

Automatic reviews include only the last interaction turn. Manual reviews include full chat history.

## Gitea Issue Tool

### Tool Factory: `GiteaIssueToolFactory`

Registered in `ToolRegistry`. Provides a single tool: `create_gitea_issue`.

### Tool Parameters

| Parameter | Required | Description |
|-----------|----------|-------------|
| `title` | Yes | Short summary of the issue |
| `category` | Yes | One of: `incorrect-answer`, `bad-delegation`, `tool-misuse`, `unhelpful-response`, `inefficiency` |
| `severity` | Yes | One of: `low`, `medium`, `high` |
| `description` | Yes | Detailed analysis: what went wrong, trace excerpt, expected vs actual |
| `suggested_fix` | No | What the agent should have done instead |

### Factory Configuration

| Property | Description |
|----------|-------------|
| `gitea-url` | Base URL of the Gitea instance |
| `gitea-token` | API token for authentication |
| `repository-owner` | Repository owner |
| `repository-name` | Repository name |
| `labels` | Default labels to apply (e.g., `ai-review`) |

### API Integration

Uses `java.net.http.HttpClient` (JDK built-in) to call `POST /api/v1/repos/{owner}/{repo}/issues`. No external HTTP dependency needed.

### Issue Body Format

```markdown
## AI Review Report

**Category:** {category}
**Severity:** {severity}

### Issue Description
{description}

### Suggested Fix
{suggested_fix}

---
*Generated by Review Agent*
```

## Trigger Mechanism

### Automatic Trigger

After main agent turn completes in `ChatProcessor`:

1. `triggerReviewAgent(Chat chat, ChatTask completedTask)` called
2. Serializes last turn (user message + agent response + timeline events) to XML
3. Submits background task to `BACKGROUND_EXECUTOR` (fire-and-forget)
4. Builds review agent via `AgentRegistry.buildUntypedAgent("review-agent", reviewMemory)`
5. If issue found → `create_gitea_issue` called → notification stored in `ReviewNotificationStore`
6. SSE handler emits `review_alert` event → UI shows dismissable banner

Controlled by `ChatProcessor.Config` boolean property `auto-review-enabled` (default: `true`).

### Manual Trigger

- Endpoint: `POST /chat/review` on `ChatServlet`
- Serializes full chat history and triggers review agent
- UI: "Review" button in chat header/toolbar

### Concurrency

One auto-review at a time per chat session. If a new turn completes while a review is in progress, the new review is skipped (debounce).

## Data Flow

```
User sends message
  → ChatProcessor runs main agent (existing flow)
    → Agent responds + tool timeline recorded
      → Response shown to user via SSE
        → ChatProcessor.triggerReviewAgent() [background thread]
          → Serialize last turn to XML
            → Build review-agent via AgentRegistry
              → Review Agent analyzes conversation
                → Issue found? → create_gitea_issue → Gitea ticket
                  → ReviewNotificationStore → SSE review_alert → UI banner
                → No issue? → Silent, no action
```

## Error Handling

- **Gitea API unreachable:** Tool returns error to review agent. Logged, no notification. No retry.
- **Review Agent LLM failure:** Caught and logged. No user impact.
- **Input too large:** Capped at configurable max (default: 50,000 chars). Oldest entries truncated first.
- **Concurrent reviews:** Debounced — one review at a time per session.

## Out of Scope (YAGNI)

- Review history/dashboard (tickets live in Gitea)
- Severity thresholds or filtering rules (LLM decides)
- Feedback loop from Gitea back to agents
- Review of the Review Agent itself
- Persistent storage of review results beyond Gitea tickets
