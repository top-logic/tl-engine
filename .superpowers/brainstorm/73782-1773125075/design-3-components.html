Security Layer

On-demand background agents need access control. The endpoint uses TopLogic's existing security infrastructure.

Security Flow: POST /chat/background/{agentName}
Request arrives │ ▼ ┌──────────────────────────────────────┐ │ SessionCheckingFilter │ Already exists in TopLogic │ → Validates HttpSession │ │ → Sets up TLContext with Person │ │ → Returns 403 if no valid session │ └──────────┬───────────────────────────┘ ▼ ┌──────────────────────────────────────┐ │ ChatServlet.handleBackgroundTrigger │ │ │ │ 1. person = TLContext.currentUser() │ │ 2. agent = registry.get(agentName) │ │ 3. roles = agent.background │ │ .trigger.allowedRoles │ │ │ │ 4. if roles is empty → allow all │ No restriction configured │ if person.isAdmin() → allow │ Admins always pass │ if AccessManager.hasRole( │ │ person, roles) → allow │ Role check │ else → 403 Forbidden │ └──────────────────────────────────────┘
Config: allowed-roles per trigger
Example 1: Restricted to admins and auditors <background scope="application" authority="advisory"> <trigger type="on-demand"> <allowed-roles>admin, auditor</allowed-roles> </trigger> ... </background> Example 2: No restriction (any authenticated user) <background scope="chat" authority="advisory"> <trigger type="on-demand" /> ... </background> Example 3: Scheduled agent (no role check needed) Scheduled agents run via Scheduler in SystemInteraction context → no user, no role check. Access is controlled by who can configure the Scheduler (admin only). Example 4: Pre/post-turn agents (chat-scoped) Triggered automatically within an existing chat session. The user is already authenticated to use the chat. → No additional role check needed (same session = same user).
