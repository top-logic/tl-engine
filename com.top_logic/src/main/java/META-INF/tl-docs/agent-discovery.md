# Agent discovery

An agent (a machine client) that knows only the URL `https://host/<context>/` of an application
finds out what the application offers through two public documents, served by
`com.top_logic.base.discovery.AgentDiscoveryServlet`:

| Path | Media type | Content |
|---|---|---|
| `/llms.txt` | `text/markdown` | Markdown in the shape of [llmstxt.org](https://llmstxt.org/): `# <application name>`, `> <summary>`, a pointer to the AI Catalog, then one `## <section>` per contribution. English, it is text for a model. |
| `/.well-known/ai-catalog.json` | `application/ai-catalog+json` | The AI Catalog: `specVersion`, `host` (`displayName`, `documentationUrl` pointing to `llms.txt`) and the `entries`, each an artifact with `identifier`, `type` (its media type, e.g. `application/mcp-server-card+json`) and exactly one of `url` and `data`. |

Both need no login, answer `GET` only, allow every origin (`Access-Control-Allow-Origin: *`) and may
be cached for an hour. The landing page `index.jsp` links the catalog (`<link rel="ai-catalog">`
and an HTTP `Link` header) and `llms.txt` (`<link rel="alternate" type="text/markdown">` and a
visible line in the body, since an agent's web fetch drops the head).

## The service

`com.top_logic.base.discovery.AgentDiscoveryService` is enabled in `com.top_logic` and reveals
nothing by itself: without an active contribution, both documents name only the application.

```xml
<config service-class="com.top_logic.base.discovery.AgentDiscoveryService">
	<instance
		summary="Manages customer orders, deliveries and invoices."
	/>
</config>
```

- The application name shown to agents (the heading of `llms.txt` and `host.displayName` of the
  AI Catalog) is the English application title `tl.title`
  (`com.top_logic.layout.I18NConstants#APPLICATION_TITLE`), set in the application's resource
  bundle - the same name users see in the browser tab and on the login page.
- `summary`: the one-line English summary below the heading of `llms.txt`; left out if not set.

If the service is not running, both paths answer `404`.

## Contributing

A module that publishes a machine endpoint implements
`com.top_logic.base.discovery.AgentDiscoveryContribution` and adds it to the service by an overlay
in its own `*.config.xml`:

```xml
<config service-class="com.top_logic.base.discovery.AgentDiscoveryService">
	<instance>
		<contributions>
			<contribution class="com.example.MyEndpointDiscovery"/>
		</contributions>
	</instance>
</config>
```

The interface has three methods, all with defaults:

- `boolean isActive()` - `false` while the described endpoint is unavailable (e.g. its service is
  not running); an inactive contribution contributes nothing.
- `List<LlmsTxtSection> llmsTxtSections(DiscoveryContext context)` - sections of `llms.txt`, each a
  title and a Markdown body (typically a short paragraph and a link list
  `- [name](url): description`).
- `List<CatalogEntry> catalogEntries(DiscoveryContext context)` - entries of the AI Catalog. An
  entry needs an `identifier` (recommended form `urn:air:{publisher}:{namespace}:{name}`), a `type`
  and exactly one of `url` and `data`; an invalid entry is left out and logged.

The catalog messages (`AiCatalog`, `CatalogHost`, `CatalogEntry`) are generated by msgbuf from
`com/top_logic/base/discovery/catalog/catalog.proto`.

## URLs come from the configured host or the request

Every absolute URL in both documents starts with `DiscoveryContext.applicationUrl()`: the configured
host alias `%HOST%` (variable `tl_host`, e.g. `https://apps.example.com`) if it is set, else scheme,
host and port of the current request as the servlet container reports them - the same rule as
`LayoutUtils.appendHostURL()` for every other absolute link of the engine - followed by the context
path of the request. `DiscoveryContext.url("/mcp")` appends a context-relative path.

Behind a reverse proxy, either set `tl_host` to the public address, or let the container apply the
forwarding headers (`X-Forwarded-*` / `Forwarded`), so that the URLs name the address the agent
used.
